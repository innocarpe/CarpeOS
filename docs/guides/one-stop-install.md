# One-Stop Local Install

Status: **two supported install paths** — npm global and git checkout. Synthetic
docs only for private paths; real runtime data stays on the operator machine.

This is the supported path to set up CarpeOS on a MacBook, Mac mini, or a new
Mac so CLI wrappers and agent MCP registrations land the same way every time.

## Path A — npm global (end users)

```sh
npm install -g @innocarpe/carpeos
carpeos setup plan
carpeos setup run --apply
carpeos setup doctor
```

Or the Codex-style one-liner:

```sh
curl -fsSL https://raw.githubusercontent.com/innocarpe/carpeos/main/scripts/install.sh | bash
```

Package source: `packages/carpeos` → npm name `@innocarpe/carpeos`.

Publishing (maintainers): use SemVer + tags, not ad-hoc publish.

```sh
# after CI green on main
node scripts/release.mjs patch   # or minor | major | X.Y.Z
git push origin HEAD
git push origin vX.Y.Z           # triggers npm publish + GitHub Release
```

Policy: [Versioning and Releases](../maintainers/versioning-and-releases.md).

Manual fallback (only if Actions cannot publish):

```sh
pnpm --filter @innocarpe/carpeos build
pnpm --filter @innocarpe/carpeos exec npm publish --access public
```

## Path B — git checkout (contributors / pre-publish)

Use this when developing from source or before the package is published.

## What it installs

| Artifact | Location (defaults) | Purpose |
| --- | --- | --- |
| Runtime home | `~/.carpeos` | SQLite store, keys, install config |
| `config.json` | `~/.carpeos/config.json` | Install metadata |
| `mcp.env` | `~/.carpeos/mcp.env` (mode 0600) | MCP env for wrappers |
| `carpeos` | `~/.local/bin/carpeos` | CLI wrapper |
| `carpeos-mcp-server` | `~/.local/bin/carpeos-mcp-server` | MCP wrapper (sources `mcp.env`) |
| Host MCP entries | Claude / Codex / Grok user config | Agents can call memory tools |

Private knowledge never goes into the public git repo. The installer only
writes under the chosen home/bin directories.

## Prerequisites

- Node.js ≥ 22.22
- pnpm ≥ 11.16
- A CarpeOS git checkout (this monorepo)
- Optional: `claude`, `codex`, and/or `grok` on `PATH` for MCP registration

## One-stop command (new machine)

```sh
git clone git@github.com:innocarpe/carpeos.git
cd carpeos

# plan only (no machine changes)
node scripts/install-local.mjs plan

# real install (idempotent; requires explicit --apply)
node scripts/install-local.mjs run --apply
```

Optional flags:

```sh
node scripts/install-local.mjs run --apply \
  --home "$HOME/.carpeos" \
  --bin-dir "$HOME/.local/bin" \
  --workspace-root "$HOME" \
  --trust-zone tz_local_default \
  --register-mcp auto
```

- `--trust-zone auto` derives a stable local zone id from the hostname.
- `--skip-build` if you already ran `pnpm build`.
- `--register-mcp none` (or `--skip-mcp`) to install wrappers/store only.
- `--register-mcp claude,codex,grok` to limit MCP registration.
- `--dry-run` is an alias for `plan`.

## PATH

Ensure the bin directory is on `PATH` (common on macOS):

```sh
# zsh example — add once to ~/.zshrc if needed
export PATH="$HOME/.local/bin:$PATH"
```

Then:

```sh
carpeos init --home "$HOME/.carpeos" --trust-zone tz_local_default
hash -r
which carpeos carpeos-mcp-server
```

## Doctor

```sh
node scripts/install-local.mjs doctor
# or, after npm global install:
carpeos setup doctor
carpeos setup show
```

Doctor checks:

- CLI/MCP entrypoints exist under the recorded install root
- wrappers and `mcp.env` exist
- `init` smoke against the home
- Claude/Codex/Grok `mcp list` mentions `carpeos` when those CLIs are installed

## What “done” looks like on a MacBook

1. `which carpeos` → `~/.local/bin/carpeos`
2. `carpeos memory context-pack --task "smoke" --trust-zone … --visible-trust-zone …` works
3. `claude mcp list` / `codex mcp list` / `grok mcp list` show `carpeos`
4. Agent sessions can call `memory_search` / `memory_context_pack` without per-repo ad-hoc config

## Hooks (separate, optional)

Installer registers **MCP** (read/propose/context-pack). Automatic session
**capture** still needs host hook templates from `adapters/` (Codex/Claude/Grok
hooks). Treat hooks as a second step after MCP is healthy.

## Cross-Mac

| Concern | Approach |
| --- | --- |
| Same tools on Mac mini / new MacBook | Re-run `install-local.mjs run --apply` on that machine’s checkout |
| Same knowledge | Private sync + trust-zone key (see cross-mac bootstrap guide) |
| Same trust zone id | Pass the same `--trust-zone` explicitly on every machine |

The trust-zone **sync key** is not generated by this installer. Sync remains
opt-in and out-of-band.

## Re-run after `git pull`

```sh
cd /path/to/carpeos
git pull
node scripts/install-local.mjs run --apply
```

Rebuilds dist, refreshes wrappers to the current checkout path, and re-registers
MCP. Safe and expected after moves/checkouts.

## Setup CLI surface

Both `carpeos setup` and `node scripts/install-local.mjs` share one interface:

| Command | Effect |
| --- | --- |
| `plan` | Print resolved paths and actions only |
| `run --apply` | Apply setup |
| `doctor` | Verify existing install |
| `show` | Print `config.json` |
| `help` / `--help` | Full parameter docs |

Without `--apply`, nothing is written. Legacy `--yes` / `-y` still map to
`--apply` but are deprecated.

## Security notes

- Do not commit `~/.carpeos` or wrapper paths with real home directories into git.
- `mcp.env` is mode `0600`.
- Installer refuses a real run without `--apply`.
